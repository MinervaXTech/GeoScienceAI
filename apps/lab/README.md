# Lab v1 (apps/lab)

React + TypeScript app with local research data, Esri World Imagery by default, and optional Google satellite visualization. SAM 3.1 and Muse run only when requested. The chat sidebar can operate the selected map through validated tools.

The chat sidebar defaults to **Muse agent**. Select Muse Spark 1.3, 1.2, 1.1 or Muse Wonder 1.0, then send a request such as “Hide SAM masks”, “Generate planning points using CHMv2 and SAM” or “Compare routes”. The choice is remembered and also controls Muse enhancement planning/review and crown-agent calls. Image generation remains Muse Image 1.0 and segmentation remains SAM 3.1. Available model IDs follow the [Meta model catalog](https://dev.meta.ai/docs/models); account access errors are displayed without fallback.

Chat operates existing controllers for layers, opacity, basemap, polygon editing, planning settings/generation/edits/exports, route comparison, SAM runs/history, image enhancement/pyramid loading, original captures, crown templates/matching/Muse detection, Earth Engine search/preview, and saved-map navigation. Polygon corners, point edits, new-map details and Earth Engine sign-in remain manual when needed; Muse opens the appropriate mode. Deletion opens the same typed-name dialog and cannot bypass it. **Notes only** saves messages without inference.

Every reply retains an expandable **Action log** with validated parameters, actual results/errors, selected model and chat request count. A message allows up to 12 actions and 13 chat-planning calls; nested SAM, image-generation and crown-agent calls are separate and may incur their normal costs. **Stop Muse** aborts further work and cancels the active tool; completed changes remain. Changing the map while a response is pending prevents that response from acting on the new map. Each paid operation (SAM, enhancement or crown agent) is attempted at most once per message; send a new message to rerun it. There are no automatic retries or silent model substitutions. Fresh tool context contains map metadata and summaries; original polygon imagery is sent only for an inspection or image-processing action, never by capturing Google tiles. The server owns `MODEL_API_KEY` and the fixed Meta endpoint. Local chat history/action logs live in Lab sessions and are included in Export JSON.


```sh
npm install
npm run dev        # http://localhost:5173
npm run preview    # serve a production build locally, including the map proxy
npm run lint && npm run typecheck && npm test && npm run build
```

- `engine/`: detector and tour algorithms copied from MetaHackathon/tools (see engine/README.md).
- `src/domain/`: label rule, validation, store functions, queries, snapshots, persistence. Pure and tested.
- `src/ui/`: React views. Data lives in localStorage key `lab.state` (schema version 1); Export/Import JSON in the header.
- Sample data loads only from the "Load sample data" button and every sample object is badged.

Google satellite remains available in the Basemap selector and uses the same MapLibre + server-side Google Map Tiles API approach as MetaHackathon. Put the following in `apps/lab/.env.local`, then restart the development server:

```dotenv
GOOGLE_MAPS_API_KEY=your_google_map_tiles_api_key
```

Enable **Map Tiles API** for the key's Google Cloud project. Use server API/IP restrictions; this is not a browser-referrer key. The `.env.local` file is ignored by Git. The key and Google's session token stay in the Vite server; the browser receives only an opaque map handle and same-origin tile URLs. Provider imagery is not written to disk. Attribution and coverage metadata are refreshed as the viewport changes. CHMv2 is an independently georeferenced overlay with visibility and opacity controls; peaks and routes use their WGS84 coordinates.

Run through `npm run dev` or `npm run preview` for the map proxy. A static `dist/` deployment alone does not include that backend; production hosting needs the equivalent `/api/maps/*` server endpoints.

## Polygon CHMv2 canopy heights

CHMv2 loads automatically for the selected map's finished polygon. It uses the selected smaller SAM polygon when present, otherwise the saved map boundary. Loading waits until drawing or editing is finished; switching polygons cancels an obsolete request without resetting the map. Added maps use their own geographic data. The bundled UPM window is used only for polygons inside that window.

The server reads bounded GeoTIFF windows from the public [Meta/WRI CHMv2 dataset](https://registry.opendata.aws/dataforgood-fb-forestsv2/) using HTTP byte ranges. It clips to the polygon, leaves zero heights and missing coverage transparent, and sets the spectrum from the positive local minimum to maximum in metres. The legend provides visibility, opacity, loading errors and retry. These are historical predicted canopy heights; acquisition dates vary, and this does not run a new model inference.

Native cells are approximately 1.19 map metres in Web Mercator. Larger selections use source overviews, labelled in the legend, with output bounded to 1024 pixels per side and at most 16 source tiles. Oversized selections show an error asking for a smaller area. Polygon results are cached for 24 hours in `.local/chmv2`; no entire global tile is downloaded. Both Vite dev and preview provide `/api/canopy/window`; static deployment requires this server endpoint. Credit: Meta/WRI CHMv2, Vantor, CC BY 4.0.

## SAM 3.1

Use **+ Add map** in Saved maps to search for a place such as **Kluang, Johor**. Click **Search** (or press Enter), then choose a result to jump there and fill the map name. Pan or zoom to refine the view, click **Draw map boundary**, place the corners, and right-click to finish before **Save map**. The exact drawn polygon is saved as the map boundary and selected as the default SAM input. **Cancel** restores the previous view and polygon. You can also use the current view with an existing drawn polygon, or enter coordinates and draw the boundary there. Each entry remembers its satellite basemap and the last selected map reopens after refresh. Saved maps are included in **Export JSON** and restored by **Import JSON**. All maps load CHMv2 for their selected polygon; UPM also retains its crown points, home and route layers. Added maps support polygon drawing and SAM. SAM outputs are associated with the map that ran them, and the latest server-saved output reopens only on its matching map. The boundary and selected SAM region persist after refresh. Captured previews remain available during the current session. Use the trash button beside an added map to open a warning dialog. You must type its exact name before **Delete map** is enabled; Cancel or Escape keeps the map. **Undo delete** restores a deleted map and its polygon.

Place search uses [Photon](https://github.com/komoot/photon) and OpenStreetMap data through `/api/geocode/search`, independently of the selected satellite provider. Searches run only on explicit submission, with a one-second server limit and a bounded 24-hour memory cache. The public Photon demo is intended for moderate use and offers no availability guarantee; for larger deployments, set `PHOTON_GEOCODER_URL` to your own Photon-compatible endpoint. Both Vite dev and preview include the search proxy; static hosting requires the same backend route.

The left sidebar has **Maps** and **Layers** icon tabs. Clicking either icon opens that panel; clicking the selected icon again keeps it open. Use the separate **Collapse map sidebar** button to reclaim map width. Layer controls, including basemap, CHMv2, map boundary and loaded results, live in **Layers** instead of covering the canvas. Switching tabs or collapsing preserves their settings. While **Add map** is open, choose **Satellite basemap** in the Maps form; existing-map layer controls stay hidden. Using a Muse enhancement opens Layers automatically.

The tools beneath the map share one tab row: **Planning points**, **SAM 3.1**, **Muse map agent** and **Crown detection**. Selecting a tab shows only that panel; clicking it again keeps it open. **Hide panel** closes the tool body and enlarges the map while leaving the tabs available. Tab changes preserve forms, previews and in-progress work, and do not run models. Arrow keys, Home and End navigate the tab row; it scrolls horizontally when space is limited. The application stays within the viewport height. The map fills the remaining workspace, and an open tool panel scrolls inside its tab instead of extending the page. Layer lists, chat messages and snapshots have their own scroll areas. On narrow screens the map and chat are stacked inside the application’s scroll area.

Set `MODEL_API_KEY` in the same `.env.local`. On a saved map, its drawn boundary is already selected for SAM. In the **SAM 3.1** tab, choose **Draw smaller area on map** to select a more specific region; the original outline stays visible. **Use whole map** restores the saved boundary. On maps without a saved boundary, select **Esri World Imagery**, click **Draw area on map** in the **SAM 3.1** tab, and place at least three corners. Right-click, click the first corner, or use **Finish polygon** to close the selection. Hold the middle mouse button and drag, or hold Space and move the mouse, to pan the map, including while drawing; panning does not place corners. Release Space/the middle button to resume placing corners. Mouse-wheel scrolling still zooms. **Undo corner** and **Cancel drawing** appear only while drawing; **Clear area** is available in the SAM tab; Enter finishes, Escape cancels, and Backspace removes a corner while the map has focus. The run button stays disabled until a valid polygon is finished; crossing edges are rejected.

Double-click a finished polygon's area or outline to reopen it for editing. Drag the visible corner handles to reshape it. While editing, double-click an edge to insert one corner at that position, including on the closing edge; double-clicking an existing corner does not duplicate it. **Undo edit** reverses an insertion or a whole drag, and **Cancel editing** / Escape restores the previous polygon. Right-click, Enter or **Finish editing** commits a valid shape. SAM stays disabled until editing is finished and never runs automatically in response to edits.

Enter one concept (default: `individual oil palm tree canopy`), then click **Run SAM 3.1**. The button crops to the selected polygon's bounds, with pixels outside the polygon transparent. Captures use the available Esri imagery up to zoom level 19 and at most 1024 × 1024 pixels. They exclude CHMv2, markers, routes, masks, legend and controls. A separate renderer leaves the visible map intact. The selected polygon is also validated on the server before any model call.

Each explicit run sends one image to `https://api.meta.ai/v1/responses` with `model: sam-3.1`, `stream: true`, `store: false`, and the concept prompt. The API key stays on the server. There are no automatic model calls or retries; concurrent runs are rejected. Meta's [published price](https://dev.meta.ai/docs/pricing-rate-limits) is US$0.0025 per image (checked 2026-11-01).

The official `@meta-sam/parser` decodes output masks. Mask contours are intersected with the selected polygon in image-pixel coordinates before conversion to WGS84 using the capture's Web Mercator corners. They remain anchored while panning and zooming. **Show SAM masks** controls the translucent grey overlay independently; thicker outlines with dark halos keep it visible against the imagery. Zero matches is a valid result; incomplete/malformed output does not replace a previous result. These segments are model predictions, not field-verified tree identities.

Results appear in the dedicated **SAM 3.1 output** panel below the map: segment count, concept, source, processed area, timestamp, confidence list, mask visibility and GeoJSON download. **Locate processed area** zooms to the run's area and outlines it with a dashed light-grey boundary. A zero-match run distinguishes empty provider output from masks that were empty or fell outside the selected polygon. Older results without diagnostics are marked as unverified. The latest capture preview is available in the output panel during the current session.

**Run log** in the output panel shows a JSON summary for every new attempt, newest first, including failures and capture cancellations. Each summary records the prompt, input size/hash, provider HTTP status and response ID, event-type counts, raw output length and a bounded preview, parser diagnostics, mask count, empty masks, masks excluded by polygon clipping, and displayed segments. Final content parts are normalized into the installed parser’s text-lane finalizer, so a response without delta events is not automatically classified as empty. Unexpected output and decoding errors remain errors and do not overwrite the last successful result. **Use** beside a completed run loads its saved masks and output details onto the canvas, turns the masks on, and zooms to its processed area without calling the model. The selected run is marked **In use** and is remembered across polling and refresh. Failed/cancelled runs cannot be loaded. Older summaries are restorable only when the complete output and matching capture geometry remain available; otherwise Use is disabled. Full completed results are now archived under `.local/sam/results/<run-id>.json` for reuse. **Download log JSON** exports the visible map’s history. The latest 50 summaries persist at `.local/sam/runs.json`; the browser also caches logs for capture/network failures. Credentials and input-image bytes are excluded. Raw provider data from older runs was not retained and cannot be reconstructed.

The latest successful result, including the selected polygon, is saved locally at `.local/sam/latest.json` (ignored by Git) and restored after refresh. Input imagery and credentials are not saved there. Download the result as GeoJSON from the output panel. Earlier whole-viewport results remain readable and are labeled as earlier runs. The research JSON export remains separate.

Esri imagery retains attribution and is subject to [Esri's imagery terms](https://www.arcgis.com/home/item.html?id=10df2279f9684e4a9f6a7f08febac2a9). Google remains visualization-only; the SAM endpoint accepts Esri captures. Running the production build requires the local preview server or an equivalent `/api/sam/*` backend as well as the map endpoints.

### Muse map agent

**Muse image source** separates analysis input from the viewing basemap. While viewing Google Satellite, choose **Earth Engine image**, sign in, **Find images for polygon**, select a scene and RGB display settings, then **Preview polygon input**. Only this preview is sent when you explicitly click Run. Changing the polygon, image, bands, range or attribution invalidates the preview. Search and preview do not call Muse. Google basemap pixels are never sent through this path.

Configure these public browser settings in `.env.local` and restart Vite:

```dotenv
VITE_EARTH_ENGINE_PROJECT_ID=your-registered-cloud-project-id
VITE_EARTH_ENGINE_CLIENT_ID=your-client-id.apps.googleusercontent.com
```

Enable and register the project for Earth Engine. Create a web OAuth client with the app's exact origin (including the local port); this popup token flow needs no redirect URI or client secret. Organization-internal OAuth clients only allow that organization's accounts. The browser loads Google Identity Services and explicitly requests the read-only Cloud scope accepted by Earth Engine's REST endpoints. The short-lived access token remains in page memory, is sent only to `earthengine.googleapis.com`, and is never put in local storage, the Muse request or server logs. Refresh requires sign-in again; Disconnect revokes the token. Each signed-in user needs the appropriate project and image-asset permissions.

Available collection searches are SkySat RGB (~0.8 m, sparse historical 2014–2016 imagery), the OpenAerialMap community subset (variable resolution/coverage), NAIP (US coverage), and Sentinel-2 RGB (10 m, last 90 days). The Sentinel time filter is applied before the footprint filter; the footprint filter matches the official client's `ee.Filter.bounds` Feature promotion. Results are bounded to 10 recent overlapping scenes and may cover only part of the polygon. Empty coverage is shown explicitly without substituting another source. **My image asset** accepts a full `projects/.../assets/...` image name. The scene's metadata, bands and provider licence information remain inspectable; attribution can be corrected before export. Display stretch is user-selected and does not change native resolution.

Earth Engine exports use `image:computePixels` with a clipped `Image.load`/`Image.visualize` expression and an explicit EPSG:3857 grid. Output is bounded to 1024 pixels per side, avoids upsampling when native metre resolution is known, and reapplies the editor's exact polygon alpha. No-data pixels remain transparent; entirely empty crops are rejected. The preview and Muse trace record asset ID, source date, RGB bands, display range, source pixel size when known, export grid size and attribution. Generated tile pyramids carry the selected source's credits. A coarse source cannot resolve individual tree crowns, and generated detail is still unverified.

Open the **Muse map agent** tab and choose an **Enhancement technique**. **GenAI reconstruction** (the UI default) sends the original polygon capture to Meta's `muse-image-1.0` image-editing endpoint, then uses the selected Muse chat model (default `muse-spark-1.3`) to compare the generated result with the original. **Run GenAI enhancement** makes one image request plus one review request, using the existing server-side `MODEL_API_KEY`. It is actual image-to-image generation, not a brightness/contrast filter. Web/image search and shell tools are disabled; only the selected Esri capture or Earth Engine preview is supplied. The restoration prompt asks for noise suppression, preservation of observed crown diameters/centres/spacing and unresolved patches left uncertain; it forbids inventing crowns or plausible unobserved fronds. These are instructions to a generative model, not an enforced geometry constraint. Spark reviews amplified noise, crown-scale changes and invented texture as well as shifted features. The source capture remains bounded to 1024 pixels per side; drawing a smaller region can retain more pixels per crown, but enlarging the generated output cannot establish new measured detail. Image generation is billed at US$0.01 per returned image plus the Spark review's token usage, per the linked Meta pricing.

**Tonal adjustments** retains the previous Muse Spark workflow: it chooses brightness, contrast, saturation and alpha-aware unsharp masking through `enhance_satellite_image`, then reviews the local tool's output. These conventional filters do not generate detail or recover real resolution. Existing saved results without a method field are treated as tonal adjustments.

The output shows original and enhanced images side by side, PNG downloads and a downloadable JSON trace with provider response IDs, usage, technique, actual returned dimensions and source/output SHA-256 hashes. GenAI image dimensions are model-selected; requests use the source aspect ratio, outputs with incompatible aspect ratios are rejected, and display output is bounded at twice the original width. The original polygon alpha is reapplied because the image model returns opaque images. Tonal mode preserves pixel positions; generative mode preserves only the requested coordinate frame and crop and cannot guarantee the positions or identities of crowns/fronds. Its output and loaded map layer are marked **GenAI preview**. The review specifically checks for invented or shifted features and bases map observations on the original. SAM and template matching retain their existing original-Esri capture path, even when the generated layer is visible; Earth Engine input is currently enabled for Muse.

Suggestions do not automatically change map layers or start SAM. Google imagery, unfinished polygons and invalid PNGs are rejected before inference. Each click permits at most two model calls, with no automatic retries. If the image model is unavailable, its error is shown without substituting filters or overwriting the earlier output. If only the review fails, the generated image remains available with a partial-output label; no analysis is fabricated. Cancel aborts further work. [Meta's image-generation guide](https://dev.meta.ai/docs/image-generation) describes the image-to-image API and its output-size behavior.

The latest Muse output for each map, including its original and enhanced PNG data, is saved locally in `.local/muse/<map-id>.json` (ignored by Git) and restored without inference. Status/output polling and opening the panel do not call the model. JSON exports omit image bytes; use the image download buttons for PNGs. The Muse panel scrolls independently, and its content does not increase the map canvas height. [Meta image understanding](https://dev.meta.ai/docs/image-understanding), [tool calling](https://dev.meta.ai/docs/tool-calling), and [token pricing](https://dev.meta.ai/docs/pricing-rate-limits) describe the underlying API.

Click **Use** below the enhanced image to convert that saved PNG into an XYZ tile pyramid and load it on the map. This is local image processing, with no new Muse request. The converter verifies the image hash and dimensions, uses the enhanced image's own frame/resolution, resamples it onto 256-pixel XYZ tiles, and downsamples lower zoom levels with alpha-aware filtering. Generative pyramids round the top XYZ zoom upward to retain the model output's pixels, with a distinct cache URL version. The polygon's transparent exterior stays transparent, and the enhancement sits above the satellite basemap and below CHMv2/SAM/crown overlays. Overzooming reuses the highest-resolution tiles without creating further image detail.

The button becomes **In use**, the map fits the enhanced area, and the legend offers **Show Muse enhancement** and an opacity slider. Tile files and their manifest persist under `.local/muse/pyramids/<run-id>/`; `.local/muse/active-pyramids/<map-id>.json` remembers the chosen run. Refresh restores this selection, with visibility and opacity remembered in the browser. A later Muse run does not replace the loaded pyramid until its **Use** button is selected. Existing pyramids are reused, and the original Esri basemap remains visible outside the enhanced footprint. [MapLibre raster source options](https://maplibre.org/maplibre-style-spec/sources/#raster) describe the tile source used for display.

### Crown template matching

Choose **Match tree crowns** on the map, then **Capture selected area**. The finished map boundary or smaller polygon supplies the region. A matching Muse original capture or Earth Engine preview can be reused without recapturing or making a model call. Clean Esri captures retain up to 1024 × 1024 pixels; all map overlays are excluded. In the captured-image preview, zoom to 200% or 400% if needed and drag a box around one distinctive crown, 6–64 pixels per side. This is a sample appearance, not a polygon mask. Drag another box to replace it.

**Template history**, below the preview, shows thumbnails of the latest 50 manual selections and matching attempts for each map, including Muse's chosen templates. Cards include source, time, pixel location/size, matching settings, run status and available candidate counts; Muse cards also show the round and selection reason. **Use** restores that sample and its settings without running detection. Reuse requires the exact same source pixels, polygon and coordinate frame; older captures remain visible as thumbnails with reuse disabled. History persists in browser IndexedDB across refreshes and recaptures. Earlier saved Muse logs and retained sample locations are recovered where available; incomplete legacy settings are labelled rather than presented as original pass settings. Selections that were never saved by earlier versions cannot be recovered.

**Find matching crowns** runs grayscale, zero-mean normalized cross-correlation in a Web Worker. Optional 80%, 100% and 120% template sizes handle modest scale changes; a scan with up to a three-pixel stride is refined at local peaks. Non-maximum suppression removes overlapping/nearby duplicates. Transparent image regions and flat templates are excluded. **Minimum similarity** defaults to 0.65; lowering it admits weaker candidates. **Minimum spacing** controls suppression relative to sample size. Changed settings apply on the next explicit run. The strongest 2000 candidates are retained if the display limit is reached; this is reported in the output.

Yellow crown circles and centres appear both in the preview and as a separately toggleable map layer. **Show crown matches** in the legend and output panel share visibility. Click a map centre for its similarity score. **Download crown matches GeoJSON** exports a point and circle polygon per candidate plus clipped review sectors, with score, scale, sample, capture frame and run settings; the candidate count is distinct from the GeoJSON feature count. Coordinates use the capture's Web Mercator frame, so matches stay anchored while panning and zooming. The selected sample is included if it passes the threshold.

Manual matching is entirely local: there are no model/API inference calls, and cancellation terminates the worker. The latest capture, sample and completed matches are saved per map in this browser's IndexedDB and restored after refresh. They are not part of the research JSON export; download the GeoJSON to share results. Similar patches are candidate crown locations, not verified tree counts, species labels or segmented crown outlines. Lighting, shadows, crown orientation, image resolution and sample choice affect both missed detections and false positives. [OpenCV's template-matching reference](https://docs.opencv.org/4.x/de/da9/tutorial_template_matching.html) describes the normalized-correlation method; this app implements its own worker-based scanner rather than loading OpenCV.

### Muse crown-detection agent

In **Crown detection**, load original Esri imagery, **Use Muse original capture**, or **Use Earth Engine preview**. Set **Detection goal**, then click **Run Muse crown agent**. A manual template is optional. The agent can choose a sample and NCC settings using the original image, execute the existing local matcher, then inspect the actual candidate count, similarities, self-only matches, errors and an annotated candidate overlay. Coverage mode defaults to 8 rounds; the Search budget offers 2, 4, 6, 8 or 12 model/tool rounds. Each new template is matched over the entire original polygon. Distinct template candidates are accumulated, then filtered by the reference crown size and strict circle separation, keeping the stronger candidate at overlaps. Size validation precedes cross-template suppression, so an oversized group cannot suppress valid smaller crowns. The combined limit is 5000 candidates; an individual matcher pass still retains at most 2000. Failed HTTP requests are not retried.

The server uses real function calls from the selected Muse model (default `muse-spark-1.3`) (`match_crowns` / `finish_crown_detection`) through `/api/crown-agent/step`; the model key remains on the server. Calls use `store: false` and are token-billed. Tool names, sample bounds, sensitivity, spacing, source PNG/frame and tool feedback are validated. The actual matcher enforces polygon alpha and sample texture; its errors can be fed back for correction. Ten-metre-or-coarser known source pixels are rejected for individual palm detection. This feature does not use generated imagery as measurement input.

The candidate layer uses yellow circles/centres and a visibility checkbox. **Crown agent run log** records each proposed tool, settings, provider request/response IDs, token usage, actual tool outcomes, source hash and stop reason. **Download agent log JSON** exports it; the latest log and successful result persist per map in IndexedDB. Cancellation, changing the active polygon or switching maps aborts pending work; a failed or cancelled run retains the last successful matches. The agent's outputs are candidate image matches, not verified tree identities or counts.

**Keep existing detections and expand coverage** is enabled by default. **Continue coverage with Muse** seeds the next search from the current image's candidates. Muse receives the aggregate overlay, recent template locations and a 4×4 image-sector distribution; sector occupancy is not a tree-detection completeness score. Sparse sectors may legitimately contain roads or gaps. Each log entry records pass candidates, net additional candidates and the cumulative count. The search moves to its final area assessment when three consecutive attempts add no candidates, the round budget is reached, or a candidate limit is reached. Unresolved assessments are labelled stopped rather than claiming every tree was found. Successful intermediate passes are checkpointed in IndexedDB so cancellation or refresh retains progress.


Crown annotation constraints use a reference diameter from the first whole-crown sample, with a default ±25% band and a maximum patch aspect ratio of 1.4. **Reference crown diameter**, **Allowed size variation** and **Extra gap between circles** control the policy. Circles use half the shorter patch dimension as radius, and no pair can have centre distance below the sum of radii plus the chosen gap. Circles are never shrunk to fit more detections. **Apply crown constraints** refilters existing raw candidates without a model call; alternate candidates are retained up to the combined limit. This is an annotation rule, not a claim that real palm fronds never overlap or that sample-sized circles are measured crown boundaries.

The final model request is reserved for an explicit **Whole-polygon area review**. Every nontransparent cell of the 4×4 image grid must receive an assessment and reason: visible palms accounted for, missed palms, no visible palms / genuine gap, or uncertain. A zero count alone never clears an area. Unreviewed, uncertain, missed and contradictory sectors remain pending; the run is not labelled complete while any are pending. Three passes without new candidates trigger the area review early. Continue coverage to search missed sectors. The map grid is clipped to the selected polygon, including holes, and its checkbox is independent of crown-circle visibility. **Inspect A1** (etc.) zooms the original preview to that sector. Changing its assessment records a user review separately from Muse's assessment. Changing candidate positions, sizes or counts invalidates affected assessments for re-review. Reviews persist with the latest per-map result and are included in GeoJSON and agent-log downloads. AI assessments and user reviews do not establish field truth.

### Approximate crown centres for path-planning studies

**Planning points**, below the map, is a separate editable point set for the selected saved map. The default coverage scope is **Whole saved map** (its saved boundary), independently of a smaller SAM selection; choose **Current selected polygon** to limit the scope. The optional **Use sparse matches only → Use crown centres for planning** starts from retained NCC match centres inside the current polygon, filters by similarity and minimum ground spacing, and keeps the stronger near-duplicate. It does not generate a regular grid or fill unobserved gaps. Circle size constraints and unfinished crown-area assessments do not prevent creating an approximate planning set. Cleanup spacing is a configurable duplicate filter, not a claim about biological planting distance. The original matcher result stays available.

Use **Add points**, **Move points** (drag), **Delete points** (click) and **Set home** while inspecting visible crowns in the satellite view. **Add visible crowns manually** also works without a matcher result. New or moved points must remain inside the source polygon and outside holes, with the point set's minimum spacing. Home defaults to the first centre and can be placed elsewhere. The floating map toolbar ends editing or undoes an edit. Up to 30 edits can be undone; point sets (up to 5000 points) persist per map in local storage. Edits invalidate routes so an old route is never shown as visiting newly edited points. A changed polygon is flagged rather than silently reusing its old point set.

**Compare planning routes** runs the existing nearest-neighbour and nearest-neighbour-plus-2-opt algorithms in a worker over the exact same points and home. It visits every point once and returns home, reporting horizontal length in a local WGS84 azimuthal-equidistant metre frame centred on the study polygon. It does not borrow UPM's coordinates, imply known heights, or run model/API inference. The worker can be cancelled and has a 30-second timeout. Planning-route 2-opt caches pairwise metre distances for dense sets while preserving the registered first-improving swap order and tolerance. Route A is amber/dashed; B is cyan/solid. Route visibility and point visibility have separate controls.

**Download planning CSV** and **Download planning GeoJSON** preserve edited coordinates, point provenance and the route visiting orders. **Download paper figure SVG** produces a standalone vector A/B comparison with the polygon, points, home, distances and an explicit approximate-data caption. These are image-derived candidate centres for a routing study, not a surveyed tree inventory. Straight-line tours do not enforce obstacle avoidance, canopy clearance or flight feasibility; in a concave area a route leg may leave the polygon. The planning set is independent of the existing UPM paper-unit snapshots and does not alter their recorded reproduction results.


**Cover whole tree area with points** estimates a dense set over the original image's tree-cover footprint without waiting for SAM, Muse or a successful template match. It reuses an original matching capture, Muse input or Earth Engine preview of the whole target polygon when available, or captures Esri imagery. Generated enhancement pixels are never used. It builds a heuristic vegetation/texture mask from RGB greenness, local variance and texture in both directions (to reject smooth grass and simple road edges), then greedily places well-spaced centres across all eligible regions, including isolated regions away from existing matches. A final pass fills residual spatial holes. Existing manual and matched centres can seed the pass; added centres are explicitly labelled `canopy-estimate`, displayed yellow, and retain that provenance in exports. Matched centres are green and manual points cyan. These are rough placement estimates, not an assertion that every point identifies a real tree.

**Estimated tree spacing** controls density (default 8 m is adjustable, not a universal palm spacing); minimum centre separation is 85% of that value. **Canopy sensitivity** admits weaker vegetation texture. The **Show estimated tree-cover mask** checkbox shows which pixels were considered. Reported mask coverage is the fraction of eligible image pixels within one spacing of a point; it is not a measured tree-detection recall. The RGB heuristic can still mistake other vegetation for tree cover or miss dark/blurred crowns. **Exclude empty region** lets the user drag a rectangular clearing on the map: points inside are removed, the exclusion is saved, and subsequent dense passes mask it out. Undo restores an exclusion edit. Changing spacing regenerates estimates across the whole mask instead of accumulating duplicates. A 5000-point limit fails visibly without committing a truncated coverage result. After generation the whole target area is fitted into view and the sparse matching/review overlays are hidden so the dense point layer is clear. Manual point edits invalidate the coverage summary; excluded regions invalidate the old mask until regeneration. Dense processing runs locally in a cancellable worker; no model request is made.

### CHMv2 and SAM constraints for dense tree points

Dense point generation now has independent **Use CHMv2 canopy heights** and **Restrict points to SAM 3.1 output polygons** controls. CHMv2 is enabled by default, with an editable minimum height of 3 m. SAM is automatically selected when a nonempty output is loaded for the current map, unless the user has explicitly disabled it. Guidance changes apply on the next **Cover whole tree area with points** run; existing points retain their original generation summary.

The canopy endpoint supplies a separate numeric `uint8-metres-base64` band: 0 is known ground height and 255 is missing or outside the clip. Numeric requests upgrade earlier overlay-only caches. Height is never inferred from spectrum colours. The numeric raster is aligned by its geographic frame to the RGB capture, including different resolutions or a rotated capture. Missing/low heights are excluded while the height constraint is enabled; local height peaks also contribute to candidate ranking. Missing-data/network failures preserve the previous point set, with no automatic RGB-only fallback. Unchecking the control explicitly allows an RGB/SAM-only run.

The SAM constraint rasterizes the union of the actual loaded segmentation polygons in geographic space, preserving holes and disconnected masks. It does not use the drawn input polygon or the masks' bounding rectangle as a substitute. These masks are intersected with the coverage area, exclusions, RGB tree-cover test and enabled height threshold. Even manual/matcher seeds must pass enabled SAM/height constraints during regeneration. Changing maps, coverage area or active guidance cancels an in-flight coverage pass. Selecting another saved SAM output does not trigger a model call; regenerate to use it.

The run summary and GeoJSON record the CHMv2 clip, source date/grid resolution, height threshold, missing/low-height pixel counts, and the SAM output's source hash, timestamp, prompt and segment count. Points record `canopyHeightM`, also exported as `chmv2_height_m` in CSV and shown in map popups. Moving a point clears its old height until regeneration; edits invalidate the prior spatial coverage summary. These remain estimated centres: historical CHMv2 and SAM/RGB imagery may differ in date and resolution, and the combination is not a verified tree inventory.
